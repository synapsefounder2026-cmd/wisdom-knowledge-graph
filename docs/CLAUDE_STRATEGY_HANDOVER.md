# 🌿 Wisdom Strategic Handover: The MCP-Native Workspace

This document defines the **"New Interaction Mindset"** for Wisdom, incorporating the modular multi-agent architecture of **Feynman** and the collaborative canvas of **Kanwas**.

## 🚀 1. The Multi-Agent "Research & Action" Engine
Wisdom now adopts a **Modular Multi-Agent** approach inspired by *Feynman*. Instead of a single model, we use a specialized "Research Pipeline":

| Agent Role | Responsibility | Implementation |
| :--- | :--- | :--- |
| **Researcher** | Sourcing papers, repos, and web data. | Skill: `deep-research` |
| **Reviewer** | Critical peer-review and fact-checking. | Skill: `critique-logic` |
| **Writer** | Drafting structured reports and PRDs. | Skill: `draft-srs` |
| **Verifier** | Link validation and source verification. | Skill: `verify-sources` |

**Execution**: Agents can scale heavy tasks (like video rendering or code execution) to local or cloud GPUs (Modal/RunPod) automatically via defined skills.

## 📄 2. Markdown Skill Files (The "Agent Soul")
Following the Feynman pattern, every Wisdom agent and workflow is defined by a **Markdown Skill File**.
- **Self-Documenting**: Instructions, constraints, and tool access are defined in human-readable Markdown.
- **Git-Synced**: Agent behaviors are version-controlled, allowing for easy updates and "Expert" personality branching.

## 🎨 3. The "Wisdom Canvas" (Shared Workspace)
Inspired by *Kanwas*, Wisdom adopts an infinite, collaborative board where humans and AI work on a **Shared State**.
- **UI Atoms**: Output from the "Research Pipeline" is delivered as interactive **MCP UI Chunks** (e.g., a "Research Map" or "Verification Dashboard").
- **Shared Context**: All agents see the same canvas, ensuring consistent context across the Growth, Lifestyle, and Wellness departments.

## 💡 4. Recommendations for Claude (2026 Vision)
- **Modularization**: Break down complex tasks into multi-agent workflows.
- **Skill-Driven**: Use the `.md` skill template to define new agent behaviors.
- **GPU-Aware**: Build skills that can request remote GPU compute for high-res media generation.
- **Verification**: Never return a fact without a verified source (using the Verifier agent pattern).

## 🧠 6. Cognitive Architecture (The "Dreaming" Agent)
Wisdom adopts the latest **Managed Agent** patterns to ensure self-evolving intelligence.

- **Dreaming (Memory Consolidation)**: When idle, Wisdom agents enter a "Dreaming" state—reviewing recent sessions, extracting recurring patterns, and compacting long-term memory. This ensures the **Knowledge Graph** (Brain2) is always refined, not just growing.
- **Outcomes (Success-Driven)**: Every task is assigned a **Grader Agent**. The primary agent iterates until the Grader confirms the output meets the "Definition of Good." No more "text wall" responses without quality control.
- **Session-Centric Infra**: We shift from "Model Calls" to **"Persistent Sessions."** Each session maintains its own containerized environment (Python/Node), file system, and state, allowing for complex, multi-day tasks with human-in-the-loop (HITL) checkpoints.

## 🛠️ 7. Extreme Engineering Standards (Telegram-Style)
To build a world-class empire, Wisdom's core must be optimized at the "Assembly" level of thinking.

- **Resource Efficiency**: Optimize for "Low-Bandwidth / Old Hardware" scenarios. Wisdom should be "Instant" even on a 5-year-old device.
- **Native Logic Core**: Share a high-performance C++/Rust core for Network, Crypto, and Media processing across all platforms. Avoid heavy, bloated frameworks where possible.
- **Customized Foundations**: Like Telegram's custom SQLite, we will customize our **Knowledge Ingestors** (Docling/Scout) to handle millions of data points with near-zero latency.

## 📈 9. The "School of Fish" Strategy (Portfolio Diversification)
Wisdom adopts a **"Small & Mighty"** portfolio approach instead of a single monolithic entity.

- **The "Small Fish" Model**: Rather than aiming for one massive $1M/month project, we build a "School of Fish"—multiple automated niche projects (Stores, SaaS, Content Hubs) each generating consistent, manageable revenue ($30K - $50K/month).
- **Niche Moats (Rào cản tự nhiên)**: We intentionally target "Hard" niches with high complexity (customization, deep research). Wisdom's agents (Feynman-style) handle the "tedious details" that scare off competitors, creating a natural safety moat.
- **The 20/80 Rule**: The system is designed to run on 20% human strategic input and 80% agentic execution. The goal is a self-running machine where the owner focuses on **"Building the Machine," not "Being the Machine."**

## 🧪 10. "Feeding the Graph" (The Pixel Mindset)
In E-commerce, the **Pixel** is the asset. In Wisdom, the **Knowledge Graph** is the asset.

- **Early Ingestion (Data Priming)**: We must "feed" the Knowledge Graph with high-quality data (Mining/Scouting) months before the peak "Execution" phase. Just as a pixel needs 1,000+ orders to find high-value customers, Wisdom needs deep context to find high-value opportunities.
- **Data > Short-term ROI**: In the early phase, the priority is **Data Quality and Volume**, ensuring the agents have a "Mature Brain" before they begin high-ticket consultancy or MMO operations.

## 🪨 11. Token Efficiency (The "Caveman" Philosophy)
To maximize our **Free Tier Strategy**, Wisdom adopts the **Caveman** philosophy: *"Why use many token when few token do trick?"*

- **Caveman Prompting**: Internal communication between agents (e.g., Lead Agent to Subagents) is stripped of filler words and polite phrases. We use fragments and direct technical instructions to reduce token consumption by up to 75%.
- **Cavemem (Persistent Memory)**: We implement a lightweight memory layer that stores only the "Core Truths" of a project, preventing context window bloat.
- **Cavekit (Spec-Driven Workflow)**: Sếp's high-level visions are immediately "compressed" into technical specs by the Creative Lead, ensuring the rest of the agentic pipeline works from a single, efficient source of truth.
